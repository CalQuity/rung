Rung verification kit design

Rung gives a developer a way to assemble checks, see what they cover, and decide what to do when the evidence is weak or missing. The project keeps its local CLI, plain files, and adapters for existing tools. Each stage makes a different decision using the same kit.

Developer workflow

StageDeveloper decisionRung surface
AdoptWhich existing commands will run, and what will setup write?rung init --dry-run, then an offline starter kit
Before editingWhich behavior must stay true? Where should a regression test fail?rung plan, approved laws and feature maps
During editingWhich checks should I run now?rung check, fresh verdicts, targeted replay and fix proofs
Before mergeDid an independent execution support this change under reviewed policy?A gate with policy preflight, a merge base, and fresh execution
After mergeCan I inspect and replay the evidence used in CI?Machine-readable reports and deliberate evidence export

Decisions

  • Keep setup and execution separate. The preview and initializer share check selection. A developer can inspect a repository without running its commands or contacting a model. Drafting with a selected provider remains a separate consent boundary because it can send code to a model and exercise generated scripts.
  • Preserve local iteration and tighten merge checks. A local ledger is a receipt that can be shared and inspected. The merge gate runs checks again and evaluates policy changes before running repository commands. Run the gate with an externally pinned CLI or action on a disposable runner. The workflow and additional rule inputs belong under repository-owner review.
  • Make artifact freshness observable. Artifact hashes are useful only when compared with the files a reviewer can actually open. Separate captures supplied by a person or agent from evidence a scripted check produced. Upload raw runtime evidence only when the project opts in.
  • Test the draft in a copy. A generated runtime script runs twice at one seed and then runs with the contents of the application sources deliberately broken. Rung keeps the candidate for review if it can still pass. The operating system write guard contains trial writes and masks common credential paths. Generated drives keep the guard on replay. A fresh copy gets the inputs and a filtered environment. The report and artifacts return to the developer's project. A reviewed check can opt out when its surrounding worker supplies the isolation or the check requires host access.
  • Escalate by risk. Start with existing checks, then choose the cheapest oracle that catches the regression. An HTTP contract, an accessibility assertion, a queue interleaving, and a pure pricing invariant need different tools. Each needs an explicit scope and a way to replay failures.

Trade-offs

A hosted reviewer could centralize execution and policy, at the cost of a new service and data boundary. A plugin-only approach would be easier to install inside one agent and harder to reproduce in a shell or CI. Rung keeps the CLI as the implementation and lets agents and CI call it.

A preflight can detect changes to declared policy files and commands in configuration. Ordinary tests and scripts still execute code from the checkout. Use repository-owner rules for additional policy paths and a disposable runner without secrets for pull requests.

Implementation language

Keep Python for this iteration. The installed wheel is about 220 KiB and has no runtime Python dependencies. On the development Mac, seven runs gave a median of 213 ms for rung --version and 535 ms for the Acme workspace preview. Checker invocations depend on the project's tools and on Java, Lean or a browser where configured. A Rust binary could simplify standalone distribution and reduce startup overhead. It would still launch those tools, and the rewrite would need to preserve the verdict format and adapters. Measure adoption friction and large-workspace profiling before changing languages.

Agent and terminal interfaces

Claude Code and Codex receive the same project-local workflow. It runs CLI commands and interprets their exit codes and structured results. The terminal uses headings, status labels and summaries, with color when attached to a TTY and plain text when requested. Check output strips terminal control sequences before logging them.

The two Stop hooks share a freshness decision and adapt it to each agent's protocol. Codex installation is explicit and leaves trust approval in Codex. The hook offers one retry and leaves the merge decision to the separate gate.

Optional remote PR execution

The adopting repository selects a reviewed Daytona snapshot and keeps its API key on a trusted GitHub coordinator. The coordinator applies policy preflight and transfers a Git bundle for the exact head. The sandbox has the same Rung version and applies the gate to the same base and head. Local execution remains the default and provider failures fail the remote gate.

The private sandbox blocks outbound network access and uses both explicit cleanup and an expiry. The coordinator validates the remote receipt and imports status and short summaries. The workflow must trust the action, snapshot and check definitions. A Git bundle shares reachable history, which limits adoption to repositories that can transfer that history. The snapshot supplies the toolchain and dependencies before the PR arrives.

Changes from Review I

  • First run and project fit. Doctor names the locked npm install command when it finds a lockfile. Dependency installation remains explicit. The focused plan provides a quick workspace command, while the default check scope includes shared inputs.
  • Lifecycle and checks. Node proofs examine cases in new files and accept named cases in edited files. Ordinary pytest checks require a passing case.
  • Integrity and CI. Formal checks distinguish model-only results from source-confirmed results. The gate protects the local entry point behind a Python module command.
  • Execution. Drafted drives retain the write guard on replay and return only the report and ordinary evidence files. Missing isolation fails the check before the drive can run. The installed wheel replayed a guarded drive on macOS and in a Linux container that permits Bubblewrap namespaces.
  • Distribution and contributor experience. The source archive includes the Acme screenshots. The contributor instructions cover checker registration and the lint warning was removed.
  • Agent and terminal output. JSON objects include a schema version and Markdown reports strip terminal controls. Hosted execution and live agent sessions require separate verification.

Changes from Review M

  • Merge preflight and pytest proof detection share a parser for Python module switches. Static environment wrappers and explicit Node test scripts are included in policy checks. Dynamic wrappers remain an explicit policy-path decision.
  • Regression proofs preserve the exact Git workspace prefix, including leading whitespace. Node proofs use runner events to retain case identity on versions whose built-in JUnit reporter omits the filename. Hosted Linux CI exposed this difference and the local regression now runs on Node 20 as well as current Node.
  • Scoped plans recommend test proofs in the workspace that owns the changed file. Inferred Cargo tests require a reviewed lockfile. A standard suite with no passing cases fails verification even if Cargo exits successfully.
  • Evidence receipts bind the shareable HTML page. A modified page makes a passing verdict stale and the report omits the unsafe link. Narrow terminals keep each artifact path within the display width while keeping short path components intact.
  • Runtime drafts now use behavior-preserving load controls where Rung can change a Python return value or disable inline browser scripts. The same named assertion must fail after the change. For other sources Rung reports a separate startup control. A Terra-authored Playwright check passed the behavior control on its first round and caught a $50 refund regression on isolated replay at seed 27623.
  • Hosted GitHub Actions started on draft PR 19 and exercised the repository’s own workflow on a hosted runner. That run caught the Node compatibility regression and three new conditional test skips. The contributor suite exercises Node and uv directly. The write-guard test exercises native enforcement on macOS and the isolation plumbing with an injected guard on other hosts. A live Daytona run requires a configured snapshot and key.

Changes from Review N

The reviewer passed all 399 contributor tests at 85% coverage and independently verified all seven hosted checks on the same revision. Two dimensions remained below 9.

  • For a custom command to claim a changed verification target, its reviewed policy must name the verification files. Maintainers can declare them with specs or workflow --policy-path arguments.
